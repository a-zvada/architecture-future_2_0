## Выбор ресурсов и параметров

Выбран минимальный, но полностью рабочий набор инфраструктуры в Yandex Cloud, достаточный для запуска доменной модели Data Mesh.

**Общий принцип выбора**: «минимально жизнеспособный стенд», чтобы быстро начать работу с доменами, но без перерасхода бюджета на старте.  
Это вариант без managed-сервисов lakehouse.  
Отдельная VM под каждый доменный lakehouse — простой способ **быстро** создать **изолированную** среду для каждого домена, куда потом можно поставить Spark, MinIO, PostgreSQL, Trino и т.д.

**Сеть и безопасность**

*   Одна VPC + две подсети (публичная и приватная) — классическая безопасная схема.
*   NAT Gateway — обеспечивает выход VM в интернет без присвоения публичных IP всем машинам.
*   Security Group с минимально необходимыми правилами (SSH + HTTP/HTTPS + outbound) — простота и безопасность на старте.

**Виртуальные машины**

*   По одной на каждый домен + event bus:
    *   Clinical, Financial, AI, CRM, Event bus.
*   Конфигурация каждой: 2 vCPU + 4 ГБ RAM (standard-v3) — минимально достаточный размер для запуска Kafka, PostgreSQL, DataHub, тестовых нагрузок и экспериментов.  
    Точные размеры CPU/RAM и дисков должны быть пересмотрены после анализа реальной нагрузки, объёмов данных и требований каждого домена.

**Диски**

*   Boot-диск: 20 ГБ (Ubuntu 22.04) — стандарт для системного диска.
*   Дополнительный диск: 100 ГБ на каждую машину (network-ssd) — для хранения данных lakehouse, логов, кэша, временных файлов.  
    Объём дисков выбран условно. Реальный размер должен быть определён после оценки текущих объёмов данных (сотни терабайт в DWH) и плана миграции.

**Не включены в автоматическое развертывание**: портал самообслуживания и API Gateway для партнесрких сервисов.  
На данном этапе неопределены требования к ресурсам и сетевым политикам.

## Декларативный подход Infrastructure as Code (IaC)

1.  **Воспроизводимость** Один и тот же код можно применить в любой момент и в любом окружении (dev, test, prod, staging) — инфраструктура будет идентичной.
2.  **Масштабируемость** Добавление нового домена, новой VM, новой подсети или изменение параметров занимает минуты и фиксируется в Git. Не нужно заново настраивать всё руками в консоли.
3.  **Версионирование и аудит** Вся инфраструктура хранится в Git-репозитории. Каждый change виден в истории, можно откатить, провести code review и согласовать изменения.
